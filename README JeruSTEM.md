# קבצי הקוד לקורס — מפגשים 2 ו-3

## דרישת קדם: מה חייב לשבת על הבקר

לפני הכול, שני קבצים חייבים להיות מועלים ל-ESP32 עצמו:

| קובץ | מאיפה | למה |
|---|---|---|
| `ssd1306.py` | מתיקיית `Upload_these_to_device` בריפו של הקורס | דרייבר המסך. בלעדיו כל הקבצים כאן ייפלו בשורת ה-import הראשונה. |
| `hw.py` | מכאן | ספריית החומרה של המפגשים. כל שאר הקבצים מייבאים ממנה. |

העלו את שניהם פעם אחת לכל ערכה, לפני המפגש. אחרי זה כל קובץ אחר אפשר פשוט להריץ מ-Thonny.

## מפגש 2 — מפיקסל למשחק

| קובץ | מתי במצגת | מה הוא עושה |
|---|---|---|
| `hw.py` | — | מסך, לחצן וזמזם במקום אחד. `display`, `pressed()`, `buzzer`. |
| `warmup_test.py` | תחנת חימום, 0:00 | שלושת סימני הבדיקה: המסך מציג READY ולחיצה משנה אותו. עומד בפני עצמו בכוונה — תקלה בו מצביעה על החומרה. |
| `motion.py` | תנועה, 1:25 | קו שחוצה את המסך. ארבעת שלבי הפריים. |
| `fps.py` | מדידת ביצועים, 2:25 | אותה תנועה עם מונה פריימים. יש בו קטע מוער להוספת חמישה מלבנים — זה הניסוי. |
| `paddle.py` | הסטיק, 2:45 | הכפתור מזיז את הסטיק, עם הצמדה לגבולות. |
| `pong1.py` | פונג, 3:15 | כדור שקופץ מארבעת הקירות. |
| `pong2.py` | סיום המפגש | המשחק המלא: התנגשות, ניקוד ומסך סיום. |

**`pong2.py` הוא נקודת הפתיחה של המפגש השלישי** — שם מעתיקים אותו ל-`meteors.py`.

## סדר העלאה מומלץ לערכה

```
1. ssd1306.py      ← פעם אחת, מהריפו
2. hw.py           ← פעם אחת
3. sprites.py      ← לפני המפגש השלישי
4. שאר הקבצים      ← לפי הצורך, או פשוט הריצו מ-Thonny
```

---

## הערה על הפינים

כל הקבצים מניחים את החיווט של המפגש הראשון:

| רכיב | פין |
|---|---|
| מסך — SCL | GPIO 22 |
| מסך — SDA | GPIO 21 |
| לחצן | GPIO 4 |
| זמזם | GPIO 23 |

אם החיווט אצלכם שונה, השינוי היחיד הנדרש הוא בראש `hw.py`.

---

## אם אין זמזם בערכה

`hw.py` מגדיר אותו תמיד, אבל רק שני מקומות משתמשים בו:
הקטע המסומן ב-`meteors.py`, ושקף הצליל במצגת השלישית.
אפשר למחוק את שניהם והמשחק נשאר שלם.
